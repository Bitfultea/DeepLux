## T3.5 isolation follow-up

The first candidate-wide CTest run used an isolated parent `DEEPLUX_APP_DATA_DIR`, but `scripts/run-mainwindow-test-isolated.sh` overrode `HOME` only when invoking `sync-plugins.sh`. Because the sync helper prefers the inherited `DEEPLUX_APP_DATA_DIR`, plugins were copied to a different profile than the wrapper's temporary `HOME`; the MainWindow acceptance could then see zero plugins. This was an environment-isolation defect in the wrapper, not a product/plugin regression.

The wrapper now runs the sync helper with `env -u DEEPLUX_APP_DATA_DIR HOME="$test_home"`, matching the later test invocation. `scripts/test_ci_plugin_isolation.py` guards this requirement. Verification:

- `python3 scripts/test_ci_plugin_isolation.py`: passed for all 6 CI sync jobs.
- `DEEPLUX_APP_DATA_DIR=/tmp/deeplux-ctest-isolated-20261113/wrong QT_QPA_PLATFORM=offscreen ctest --test-dir build-merge-check --output-on-failure -R '^(test_mainwindow|ui_capture_mainwindow)$'`: `test_mainwindow` passed; `ui_capture_mainwindow` failed as expected because it is a direct process that correctly honors the deliberately wrong override. This was a boundary probe, not a delivery gate.
- With `HOME=/tmp/deeplux-ctest-isolated-20261113` and `DEEPLUX_APP_DATA_DIR=/tmp/deeplux-ctest-isolated-20261113/.deeplux`, targeted `ui_capture_mainwindow` passed 1/1.
- Under that same isolated environment, full CTest passed **134/134** in 142.42 seconds, `-j4`. Log: `/tmp/deeplux-hardening-ctest-final.log`, SHA-256 `d3365cc627fbcca98b28b358658e8f43d6348acca536d97b1259c3d4ceac279d`.
