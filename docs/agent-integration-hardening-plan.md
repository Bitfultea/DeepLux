- 状态：工程验收完成（B0~B6）；使用验收（真实模型/Windows/实际 MCP 客户端）仍未验证，见验收记录。
- 编制日期：2026-10-28。
- 评审基线：`9cf9aa7`，包含第一迭代 `af56b5b`、第二迭代 `0fd1aa2` 及集成修正。
- 对标源码：[visionflow-studio，dcbccb3](https://github.com/agentthink/visionflow-studio/tree/dcbccb3d961f446e8127e74bb7feb42d20dbdac1)。借鉴机制，不以工具数量或功能完全相同为验收目标。
- 关联设计：[路线图](agent-improvement-roadmap.md)、[第一迭代](agent-iteration1-design.md)、[第二迭代上半](agent-iteration2-design.md)、[第二迭代下半](agent-iteration2b-design.md)。

## 1. 目标与边界

目标：让 Agent 能可靠完成“执行、读取结果、诊断失败、重新规划、经授权修正”的闭环；权限、确认、历史与审计对同一操作给出一致解释。

本轮修复失败分类、上下文裁剪、入口权限、确认失效、MCP 取消与输入边界；补齐日志隐私开关和可重放验收。保持现有 Qt 架构、工具名称和兼容字段，不新增 Agent 框架。

不包含：MCP 写操作、单节点可取消执行、参数扫描、多服务商管理、自动长期记忆、SAM 推理改造、大规模 RunEngine 重构。`runMode=node` 仍明确为仅改参、不执行，不能宣称完成单节点验证。

## 2. 执行纪律

1. 开始前记录 HEAD、工作区、构建目录来源、依赖与测试结果。若基线已变化，先审查增量，不能覆盖他人修改。
2. 从实际基线新建 `agent/integration-hardening` 分支，不直接改写 main 历史。
3. 每批先补判别性测试，再实现；以父提交复跑或临时移除修复证明测试能识别缺陷。设计新增行为需明确标注，不伪称历史回归。
4. 每批一个可独立审查的提交；实现与相应测试一起提交，报告实际命令、结果与未测项。评审通过后再推进依赖批次。
5. 主工作区、用户插件目录、API Key 和真实工程不作为破坏性测试材料。插件测试使用临时 HOME，清除 `DEEPLUX_APP_DATA_DIR` 干扰。
6. 不以 stub 结果替代真实模型验收，不以 Linux 结果替代 Windows 验收，不因日志没有崩溃就宣称竞态清零。

## 4. B0：先统一行为契约

### 4.1 工具结果与续跑

- 工具调用成功不等于被测流程成功。集中判断调用结果，保留既有 `error/code/success/errorMessage` 兼容字段，禁止各入口自行猜测。
- 任意普通工具失败（包括 `run_failed`、`invalid_parameter`、`node_not_found`、连接冲突及未分类 `tool_error`）：停止本批剩余调用并为其生成 `skipped_after_failure` 结果；将具体失败结果回传模型诊断和重新规划，不自动重放原调用。
- 用户取消、权限拒绝、工程上下文失效，以及 `timeout`、断点、重入、`already_running` 等运行控制终态：本轮结束，不续跑。超时仍按已有协议请求引擎停止，不声称同步执行已立即停止。
- 重新规划中的每次写操作仍走当前权限与确认。保留现有轮数、工具数量和全局 deadline，不允许失败恢复重置这些预算。
- 每个 assistant tool_call 恰有一条对应 tool 结果，包括跳过和拒绝；跳过不记为执行成功。直接 Bridge 调用不能凭空创建模型 tool 历史。
- 调参运行失败时保留已应用参数，明确告知；撤销仅覆盖工程编辑，不承诺撤销已经发生的文件或设备副作用。

### 4.2 上下文保护

删除现有“整个最新 user turn 永不裁剪”与“单轮硬上限必须裁剪”相互冲突的规定，改为以下明确规则：

- 必须保护当前真实用户请求、在途 assistant/tool 调用组及最近完整工具结果组。
- 自动回灌的图片消息属于原用户任务，不视为新用户任务；使用内部来源标记区分，不修改对外模型协议。
- 优先删完整旧用户轮，再删当前任务内更早的完整工具组；不得拆组、不得伪造成功、不得用旧结果替代当前结果。
- 保护集合自身超过 token、消息数或图片预算时，显式返回 `context_budget_exceeded`，不再发模型请求。保留可诊断的本地记录。
- 本轮不开发自动摘要；大结果沿用既有有界截断，并明确标注截断。

### 4.3 B0 验收

统一第一迭代通用错误契约、run_flow/tune 示例、失败续跑描述；统一第二迭代 I4、伪代码和预算测试；列出所有有意行为变化。按 B1 至 B6 的用例逐项审查，无同一输入对应不同终态的描述才可进入实现。

## 5. B1：失败闭环与审计一致性

修改范围：`src/core/agent/AgentActor.{h,cpp}`、`AgentController.{h,cpp}`，必要时修改审计序列化；复用现有结果对象，不另建执行框架。

实施步骤：

1. 梳理全部工具返回路径及消费者：批量执行、对话历史、直接 IPC、MCP、审计、UI。
2. 用一个共享结果判定入口替代散落的 `contains("error")` 判断，确保 `success=false` 不会变为成功。
3. 首次失败后停止旧批次，为全部未执行调用补齐跳过结果；恢复模型前先检查取消、工程有效性和预算。
4. 普通工具失败均回传模型继续诊断；取消、权限拒绝、工程上下文失效和运行控制终态不续跑。新的写操作重新授权，不继承旧批次确认。
5. 对运行失败、跳过、拒绝分别记录审计，执行计数不得包含跳过项。

必须新增或加强的测试：

- `run_flow` 运行失败后跟随 `set_param`：后者零执行，审计为失败，后续模型请求含完整失败与跳过结果。
- `tune_node_and_verify` 失败：参数保留且可撤销；脚本化模型收到失败，下一轮生成修正，Advisor 必须再次确认。
- 取消/超时/断点/拒绝：模型请求计数不再增长，后续写操作零执行。
- 连续运行失败：达到既有轮数或 deadline 后停止，不能无限恢复。
- 串行多工具、提前校验拒绝、部分执行失败：发送到模型的每个调用 ID 恰配对一次。

验收：`test_agentactor`、`test_agentcontroller`、`test_agentclosedloop`、`test_agentaudit` 通过；覆盖真实序列化请求，不只检查内部列表。

## 6. B2：权限统一与过期确认

修改范围：AgentController、已有 ProjectManager 事件接线和必要的 UI 提示；不新增独立权限框架。

实施步骤：

1. 所有工具入口使用 ToolSchema 的 readOnly/dangerous 元数据判定。Observer 允许只读；Advisor 写操作确认；Autopilot 危险操作仍确认；MCP 保持全部写操作拒绝。
2. 混合批次逐项判定：允许的只读调用可执行，拒绝项生成结构化结果，绝不因批次含读工具放行写工具。
3. 待确认时保存工程会话身份和修改版本；优先复用已有事件/版本，没有则增加最小内部递增序号，不以裸指针或路径作为唯一身份。
4. 工程切换/关闭、目标删除、外部参数修改使旧确认失效；确认按钮及排队 lambda 均复核，禁止只在展示弹窗时检查。
5. 进入嵌套等待期间发生取消、工程切换或权限变化，下一项工具执行前再次检查。Agent 自身已授权修改不能被误认成外部变更；显式 open/create 工具成功后保守终止旧批次其余操作，让模型读取新工程再规划。

必须验证：Observer 经 Chat/IPC/MCP 均可查询且不能写；混合读写批次不越权；A 工程确认前切换到含同 ID 的 B 工程，A/B 都不被旧确认修改；确认入队后切工程同样拒绝；等待期间降权后剩余写操作不执行；合法确认只执行一次。

用信号、事件队列或测试屏障构造顺序，不用固定 sleep 碰撞窗口。保留现有工程切换清空撤销栈测试。

验收：`test_agentpermissions`、`test_agentcontroller`、`test_agentactor`、`test_mcpbridge`；真实 GUI 至少验证一次“确认前切工程”的提示与参数不变。

## 7. B3：上下文保护与预算失败关闭

修改范围：AgentController 和必要的内部消息来源字段；沿用现有历史容器，不引入记忆服务。

实施步骤：标记真实用户请求与自动回灌消息；按 B0 定义计算保护集合；裁剪完整旧单元；在发送前校验调用配对与预算；保护集合超限时结束本轮并显示可操作提示。

必须验证：

- 长用户文本加待执行工具调用：不因裁剪丢失该调用；超限则不发请求。
- 多轮调参裁剪旧组后，当前请求及最近失败/成功结果仍保留，工具 ID 完整配对。
- 自动回灌图片不产生新的用户任务边界；原任务意图仍保留。
- 单轮超过消息数限制、图片预算超限、系统提示本身超限：确定性停止，不能循环裁剪或偷偷发送超限请求。
- 旧孤立 tool 消息可清理；在途调用不得当作历史损坏删除。

验收：更新与新契约冲突的旧测试时说明原因；检查实际发给测试 HTTP 服务的 messages，并同时断言预算、顺序、配对和当前任务内容。

## 8. B4：MCP 取消与输入边界

修改范围：`src/app/mcp/main.cpp`、`McpStdioServer`、`AgentBridgeClient`、`tests/test_mcpbridge.cpp`。

实施步骤：

1. 把阻塞式整行读取/同步转发改为“输入可继续接收、桥接业务仍单请求在途”。优先利用 Qt socket 的异步信号；stdin 适配需同时支持 Windows 管道和 Linux，不能仅依赖 Unix 文件描述符。
2. 维护当前请求 ID 与取消状态。取消只抑制本地迟到响应，不声称能够中止 GUI 内已经开始的操作；不能误取消下一个请求。
3. 有界增量读帧，沿用现有 4 MiB 帧上限；超过上限立即拒绝并丢弃到换行，下一帧仍可解析。EOF 半帧行为需写入测试。
4. 异步化时同时限制待处理队列条数及累计字节；B0 冻结具体常量，测试注入较小限额覆盖边界，禁止新增无限队列。
5. 区分没有 id 的通知与当前文档允许的 `id:null` 请求。保持既有兼容承诺；若要收窄协议，必须单独记录兼容性变更，不能静默不回应。

必须验证：假桥挂起时发送取消，确认在假桥释放前已消费取消；释放后原结果不输出，下一请求正常；未知/重复/过期取消不影响其他 ID；超长无换行输入缓冲有界；错误帧后合法 ping 正常；队列满时明确拒绝；EOF/关闭无挂起；stdout 仅包含协议帧。

验收必须包含启动真实 `deeplux-mcp-bridge` 子进程的黑盒测试，不能只调用 processLine。取消用屏障证明消费顺序；测试超时只作防挂死保护。Linux 与 Windows 均需验证 stdin、取消和退出。

## 9. B5：最小隐私设置改进

目标不是增加日志平台，而是让现场用户能知道并控制记录内容。

1. 在现有 Agent 设置页增加审计、失败请求正文记录开关，绑定已有配置键。失败正文对未显式配置的用户默认关闭，已有显式值尊重用户选择。
2. 审计开关默认行为保持兼容；说明工具参数可能含业务信息，脱敏规则不能保证识别任意机密。
3. 禁用失败正文日志时不写新正文；已有文件不自动删除，界面明确关闭不等于清除旧记录。
4. 保留轮转、保留期、图片字节排除、写盘失败不影响对话等现有保障。

验收：默认/显式开启/关闭/重启四态；关闭后模拟 BadRequest，磁盘无新增正文；开启后脱敏、限额有效；写失败不影响对话；深浅主题和窄窗口没有遮挡。使用假凭据，不把真实密钥写进测试产物。

## 10. B6：综合验收

### 10.1 确定性闭环

复用现有 QtTest、脚本化 LLM、假 HTTP/IPC 服务与临时工程，至少覆盖：

| 场景 | 最终断言 |
|---|---|
| 正常执行、读指标、导出图像 | 下一轮请求收到本次结果和图像，模型完成总结 |
| 故意运行失败、诊断、改参、再运行 | 首次失败准确反馈，旧批次写操作不执行，新修改经过授权，最终数值符合预期 |
| 用户拒绝修正 | 参数不变、拒绝结果配对、停止自动续跑 |
| 等待中停止或降权 | 后续写操作零执行，终态与权限一致 |
| 确认前切换工程 | 旧操作失效，不影响新工程 |
| 长对话和大结果 | 请求合法且在预算内，或明确停止；不丢当前关键反馈 |
| 外部 MCP 诊断和取消 | 只读可用、写拒绝、迟到结果不返回 |

不要只断言“返回成功”；同时检查工程参数、输出数值、LLM 实际请求、工具次数、审计、撤销和终态。B1 至 B4 的关键边界定向重复至少 20 次，仍不能据此替代 TSan。

### 10.2 构建和隔离测试

开始前核验 `build/CMakeCache.txt` 的 CMAKE_HOME_DIRECTORY 指向当前工作区。以下是 Linux 模板，每条命令单独执行并保留退出码；依赖路径不写入仓库。

```bash
cmake --build build -j4
TEST_HOME=$(mktemp -d /tmp/deeplux-agent-hardening.XXXXXX)
env HOME="$TEST_HOME" bash scripts/sync-plugins.sh build
env -u DEEPLUX_APP_DATA_DIR HOME="$TEST_HOME" QT_QPA_PLATFORM=offscreen ctest --test-dir build --output-on-failure -j4
git diff --check
git status --short
```

新增测试注册到 CTest，实际通过数随新增用例变化，不硬编码为历史 86/86。格式检查仅针对改动 C++ 文件。MCP 子进程与网络 stub 需要本地套接字权限，环境拒绝应单独记录并在合适环境复跑。

Windows 按 [windows-build.md](windows-build.md) 执行构建、插件同步与 CTest；不能直接套用 Linux 的 .so 同步脚本。

### 10.3 真实使用验收

- 在临时工程、非生产设备连接下，用实际配置的模型服务完成正常闭环、失败修正、用户拒绝和中途取消各三次。
- 至少一个视觉模型验证导出图像确实进入请求；一个纯文本配置验证降级，不要求增加新 provider。
- 记录模型标识、是否流式、图像/工程来源、预期与实际输出、请求次数、确认次数和终态；报告中不含密钥或客户机密。
- 用实际 MCP 客户端验证发现、只读查询、写拒绝和取消。单独列出客户端及版本，不能以假桥替代。
- Linux/Windows、真实 LLM、MCP 客户端分别有结论。CPU 验证不能证明 CUDA 推理通过；本轮不改 CUDA，既有证据只能标注沿用。

## 11. 交付与批准规则

每批报告固定包含：基线/交付提交、修改文件、行为变化、判别性测试证据、定向/全量结果、未测项与风险。UI 改动另附截图。设计变化先更新对应章节，再同步路线图，避免新的互相矛盾描述。

最终状态分两级：

- 工程验收通过：B0 至 B5 完成，确定性测试和全量门禁通过，无未解决的阻塞缺陷。
- 使用验收通过：真实模型、实际 MCP 客户端和声明支持的平台均有证据。缺环境时标记未验证，不写成已通过。

最终合并前 fetch 远端，检查新增提交及冲突，集成后重新运行受影响测试和全量门禁。合并、rebase、推送需要当时明确授权；本文不自动授权这些操作。回退只针对本轮独立提交，不重置用户工作区。

| # | 行为变化（相对 9cf9aa7） | 终态/口径 | 对应用例 |
